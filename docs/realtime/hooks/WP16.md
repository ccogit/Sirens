# WP16 – Einbau durch KETTE-31

Hinter Feature-Flag, Host-/Origin-Prüfung, Session- und Asset-Berechtigung.
Server legt Aufnahme-Wurzel außerhalb des Musikordners fest; keine Client-Pfade.

## AudioCore

Nach Start-Klick Dienst-Export anlegen, dann:
```js
import {Recorder} from "./recorder.js";
const recorder = await Recorder.attach(core, send, finish);
recorder.start();
// Vor core.destroy() und bei Stop:
const result = await recorder.stop();
```
Stummer separater Worklet am Ausgang core.node (nach Limiter). Acht Transferpuffer
à 2048 Frames; bei Erschöpfung expliziter Abbruch. Aufnahmeframe ab Null, monoton
auch bei Seek. send(startFrame, bytes) muss bestätigten nächsten Frame liefern,
finish() schließt Dienst-Export auch bei Fehlern. Beide mit Timeout; bei
Suspend/Destroy Recorder zuerst stoppen bzw. fail() aufrufen.

## Neue Adressen (Vorschlag, kein Eingriff in eingefrorenen v1-Vertrag)

- POST sessions/{id}/recordings: JSON name, sample_rate; servergenerierte ID,
  Recording(root, music_root, name, sample_rate) registrieren.
- PUT sessions/{id}/recordings/{rid}/blocks/{start_frame}: application/octet-stream,
  Content-Length 8..16384, Vielfaches von 8; kein Chunked-Encoding. Float32 LE L/R.
  Vor Lesen Länge und Session prüfen. Recording.append(body, start_frame) liefert
  next_frame als JSON. Bei Fehler Aufnahme beenden; kein blindes Wiederholen.
  Separater Exportpfad, nicht Sidecar-PCM (Restblock kann kleiner als 256 sein).
- POST sessions/{id}/recordings/{rid}/close: Recording.stop(), idempotent;
  Export-Assets registrieren; keine absoluten Pfade ausgeben.
- POST sessions/{id}/exports: save_session(root, music_root, JSON); Datei-ID
  registrieren. GET sessions/{id}/exports/{eid}: load_session mit registriertem
  Relativpfad. JSON vor Parsen auf MAX_SESSION_BYTES begrenzen.
- Beim Start verwaiste .part-Segmente mit repair(root, relative, music_root)
  reparieren; Fehler sichtbar protokollieren, keine aktiven Aufnahmen reparieren.
  Globale Quota und Anzahl paralleler Aufnahmen begrenzen, Lease bei Abbruch.

Replay: Anfangsparameter setzen, Timeline über Session-Befehle zeitadressiert
abspielen; Hashes prüfen, Assets anhand IDs auflösen. replay_parameters(value,
frame) liefert CPU-Parameterzustand. Keine bitidentische Modellwiedergabe zusagen.

Format: WAV PCM24 Stereo LE, Rundung und Sättigung, Master-Limiter verhindert
Clipping. Segmente eigenständig abspielbar, RIFF-Datengröße maximal 4294967256
Bytes. Standard-Gesamtlimit 16 GiB Nutzdaten, 1 MiB Reserve.
SESSION_SCHEMA in recordings.py ist separates Dateischema.
