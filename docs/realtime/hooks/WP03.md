# WP03 – Einbau (Koordinator / WP06)

- Ein gemeinsamer GPUManager pro Dienst; Reserve konfigurierbar über `GPUManager(reserve_bytes=...)`, Vorgabe 2,5 GiB. Periodisch (z. B. jede Sekunde) `reconcile()` aufrufen, nicht im Audio-Callback; bei False Dry/Fallback. Keine fremden Prozesse beenden. Die bestehende CUDA-Sperre in server.py erst nach gemessener Freigabe umstellen.
- Registry über `ModelRegistry(mock_enabled=cfg.rt_mock)`; lokale .env-Variable SIRENS_RT_MOCK_PYTHON optional, Standard sys.executable nur für Mock. Für echte Modelle Interpreter absolut aus lokaler .env, Manifest mit gemessener/freigegebener Capability; kein Download.
- Pro Modellinstanz `WorkerSupervisor(registry, name, gpu=manager, profile="Performance")` erst nach Nutzeraktion mit `start(user_action=True, priority=Priority.INTERACTION)`; dann load, warmup, process, unload. Mock process: Little-Endian Float32 Stereo als bytes, getrennt vom JSON-Frame, payload audio_bytes kündigt genau diese Binärlänge an; Antwort (payload, bytes). Keine Pfade/Argumente aus HTTP an den Supervisor weiterreichen. Bei Ablehnung Fallback; ein CPU-Neustart verwirft Modellzustand, daher erneut load/warmup. Keine automatische Wiederholung eines Auftrags.
- Bei Session-Ende und Dienst-Shutdown alle Supervisoren mit close() beenden; cancel() beendet den Workerbaum und gibt Lease frei. Queue-/Deadline-Zähler und Underruns im Session-Layer aggregieren; GET gpu liefert derzeit allein GPU-Snapshot (Zähler 0 ohne Sessions). Die WP01-Routenprüfung, die GET gpu noch als 503 erwartet, muss durch den Koordinator auf 200 + Schema umgestellt werden. Keine Änderung an WP01-Testdatei durch KETTE-21.
- Profile sind initiale Richtlinien, kein gemessenes Leistungsversprechen. Zielrechner: python -m sirens.realtime.telemetry (JSON, vram_free_bytes zusätzlich zum HTTP-Vertrag); Prozess- und Audio-Gate separat im G2/G3.
