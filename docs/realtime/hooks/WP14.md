# WP14 – Einbau der Performance-Tools

Nur bei aktiviertem SIRENS_RT_ENABLED und nach Freigabe der jeweiligen Hörprüfung; bis dahin als Offline-Prototyp deaktiviert/benannt. Keine neue AudioContext-Instanz. Keine Modelle starten. In der späteren Suite (WP17) beim Aufbau des Performance-Bereichs importieren:

```js
import {drumArchitect, drumPreset, PerformanceScheduler, savePreset, loadPreset} from "./realtime/drum_architect.js";
import {stemCrossover, crossoverPreset} from "./realtime/stem_crossover.js";
import {acidTransformer, acidPreset} from "./realtime/acid_transformer.js";
```

Der bereits geöffnete AudioCore ist Eigentümer des einzigen Ausgabepfads. Nach Nutzeraktion im Controller genau einen PerformanceScheduler(core) anlegen. Der Controller ruft das gewählte Werkzeug mit rate=core.rate und Länge in Quellframes auf, zeigt alle warnings vor dem Abspielen an, übergibt result.track mit setTrack und ruft play(source) / seek(source) / stop() auf. Vor Wechsel der Suite stop() aufrufen. Das Rendern ist offline und nicht in einem AudioWorklet auszuführen; größere Sessions in einem separaten Browser-Worker vorbereiten. Mono-Prototyp: der Controller muss vorhandene AudioBuffer auf core.rate resampeln und kontrolliert zu Mono mischen, bevor er deren PCM als Float32Array übergibt. Keine Veränderung der Originaldateien.

- Drum: vorhandenes Demucs drums, optional vorhandene Einzelspuren; onsets [{kind,frame,velocity}], manuelle Korrekturen als [{index,frame,velocity}]. Keine künstliche Einzelstem-Trennung. Ohne getrennte Spuren kein Replace, Double nur mit explizit klassifizierten Einsätzen. UI muss manuelle Klassifizierung anbieten; Onset-Frames aus WP10 sind nicht klassifiziert.
- Crossover: maximal vier bereits dekodierte Stem-Mischungen {id,track,grid,key,sourceFrame}; Auswahl und Gains im Controller, Tonart aus WP10 (Dur/Moll), Transposition begrenzt und manuell; Konflikte anzeigen. Keine zusätzliche Modell-Registry-Anbindung bis Freigabe.
- Acid: vorhandene Basic-Pitch-Noten aus Stem Studio als Vierertupel oder WP10-Frameobjekte; Onset-only mit expliziter MIDI-Vorgabe, keine vorgetäuschte Tonhöhenerkennung. Bass-PCM bei hideBass nicht hinzufügen; übrige Stems im Controller getrennt behandeln.
- Presets: savePreset("drum"|"crossover"|"acid", validiertes Preset), loadPreset mit zugehöriger Preset-Funktion; Quellen separat in der Session referenzieren. Rack-Preset und Parameter enthalten, keine PCM-Daten im Preset.

Keine gemeinsamen Dateien in WP14 ändern. Aufruf und Hörprüfung: node benchmarks/performance/render.mjs <neues externes Verzeichnis>; neun WAV-Dateien in einem Browser lokal öffnen, je Demo Einsatz, Klang, Pegel, Artefakte und Warnung prüfen. Bericht: python benchmarks/performance/report.py <baseline.json> <render.json> <neue Ergebnisdatei.json> --note "drum-double: ..." (je Demo wiederholen); python benchmarks/result.py <Ergebnisdatei.json>. Keine erzeugte Audiodatei einchecken.
