## Sitzungspool

In Session.__init__ (sessions.py) nach Zuweisung des Managers:

```python
from .worker_supervisor import SessionWorkers
self.model_workers = SessionWorkers(self.manager.registry, self.manager.gpu,
    music_root=self.manager.sources.cfg.music_root,
    realtime_dir=self.manager.sources.cfg.realtime_dir)
```

Nur nach expliziter Nutzeraktion, Modellname aus Registry, Controls aus Manifest:
`worker = self.model_workers.preload(name, params, user_action=True, priority=Priority.NEXT_SECTION)`.
Wiederholte Streaming-/Chunk-Aufrufe nutzen dieselbe Instanz; beim Entfernen des Moduls
`self.model_workers.unload(name)`, bei Panic/Close/Shutdown im finally `self.model_workers.close()`.
Nicht zusätzlich zu einem bereits laufenden Einmal-Worker starten. Bei Ablehnung Busy/Dry anzeigen.
Dateijobs sind weiter Einmaljobs: request_file_job beendet den Prozess vor Veröffentlichung,
damit keine nachträglichen Schreibzugriffe auf veröffentlichte Assets möglich sind.
Ein sicherer persistenter Dateijob-Vertrag braucht noch eine separate Lösung; nicht einfach stop() entfernen.

## Lease-Diagnose

In routes.dispatch nach Origin-/Flag-Prüfung, neben GET gpu:

```python
if method == "GET" and parts == ["gpu", "leases"]:
    sessions = getattr(handler.app, "rt_sessions", None)
    return handler._json(200, {"leases": sessions.gpu.lease_snapshot() if sessions else []})
```

Separater Endpunkt, kein Zusatzfeld im eingefrorenen Telemetrie-v1-Schema.
Im Shell-Statuspoll zusätzlich GET /api/rt/v1/gpu/leases über vorhandenen API-Client,
`gpuText(gpu, leaseResponse.leases)` verwenden; Fehler als unbekannt anzeigen.
Die Statuszeile ist keine gemessene Peak-Angabe, sondern reserviertes Budget.
Kein neuer Worker/Download durch Poll.

## Profile / Visualisierung

Der bestehende POST /api/rt/v1/profile ändert die globalen Limits. Supervisoren ohne
festes Profil übernehmen die aktuelle Queue-Grenze bei jedem neuen Request.
Bei expliziten Obergrenzen gilt das Minimum. Downgrade bei aktiven überschüssigen
GPU-Leases wird abgelehnt. Bestehende Visual-Drosselung aus WP26 auch auf alle neuen
Visualisierungen anwenden: Performance normal, Eco/Neural/Training/Render gedrosselt.
Keine Änderung an Audio-Takt oder Sample-Rate. Keine Freigabe neuer Modelle.
