# WP25 – Dateijob in der Lab Shell

Die Backend-Routen und das eigenständige ES-Modul sind in KETTE-28 verdrahtet.
Die gemeinsame `web/js/realtime/shell.js` gehört laut Kettenregister zur parallelen KETTE-43;
dort den folgenden Einbau durchführen, nicht aus KETTE-28 heraus ändern.

1. In `shell.js` neben den anderen Imports:
   ```js
   import {mountSeparationJobs} from "./advanced_stems.js";
   ```
2. In `createLabShell().mount(root)` vor `root.replaceChildren(...)`:
   ```js
   const advancedHost = h("div", {});
   ```
   Diesen Host als Kind der vorhandenen RT-Sektion nach Bibliothek/Transport ergänzen.
   Nach dem Aufbau:
   ```js
   const unmountAdvanced = mountSeparationJobs(advancedHost, {
     selectedPath: () => song.value
   });
   ```
   Beim Dispose **vor** `root.replaceChildren()` `unmountAdvanced()` aufrufen.
   Der Mount startet keine Worker. Nur expliziter Klick startet einen Offline-Job.
   Die vorhandene Meldung „keine neue Trennung“ entsprechend korrigieren. Keine
   synthetische Fixture als echter Song, kein DrumSep, kein Streaming.
3. Der eigenständige Offline-Vorspieler nutzt ein HTML-Audioelement, keinen zusätzlichen
   AudioContext. Die endgültige Shell muss bei Panic, Songwechsel und Transportwechsel
   auch dieses Audioelement stoppen bzw. den Mount neu aufbauen, damit keine parallele
   Wiedergabe entsteht. Alternativ `onMix(samples, rate)` an den vorhandenen Player
   anschließen; nur eine aktive Wiedergabe. Hörprüfung auf Zielrechner erforderlich.
4. Standardexport über PUT an den serverseitigen RT-Exportordner. Kein vom Browser
   übergebener Dateipfad. `onExport` nur überschreiben, wenn der alternative Export
   die gleichen Pfad- und Publikationsregeln erfüllt.

## Steuer- und Ergebnispfad

- POST `/api/rt/v1/separation/jobs`, JSON `{"pfad":"Album/Song.wav","model":"roformer"}`
  (alternativ htdemucs); 202 mit Offline-Jobdetail.
- GET `/api/rt/v1/jobs/{id}` / POST `/api/rt/v1/jobs/{id}/cancel` mit leerem JSON:
  bestehendes v1-Job-Schema. Der Offline-Job hat als technische Korrelation
  `session_id=id`, aber keine Mock-Session. `asset_id` ist bei Erfolg die Originalquelle.
- GET `/api/rt/v1/separation/jobs/{id}`: Modell, Cache-Treffer, Rückfall,
  Asset-ID je Spur und ggf. Peak-VRAM. Keine absoluten Dateipfade.
- GET `/api/rt/v1/assets/{id}` (v1-Metadaten), GET `/api/rt/v1/assets/{id}/audio`
  (WAV, gleicher Origin).
- PUT `/api/rt/v1/jobs/{id}/export` mit vollständigem PCM16-Stereo-WAV in
  `application/octet-stream` (44,1 kHz, Framezahl der Originalquelle).
  Ergebnis: servergenerierte ID und relativer Pfad unter RT-Ordner.

Die neue Offline-Detailantwort ist eine Ergänzung für die Mehrspur-Ausgabe;
eingefrorene Schemadateien und Mock-Adressen werden nicht geändert. Die Zuordnung
der Offline-Korrelation zum Pflichtfeld session_id bitte bei der Abnahme ausdrücklich prüfen.
