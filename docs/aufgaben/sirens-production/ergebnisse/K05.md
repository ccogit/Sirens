## Aufruf und Messprotokoll am Zielrechner

Der Hauptprozess importiert ausschließlich Standardbibliothek und Sirens. Mix und Return-Messung verwenden je einen separaten Dateijob (UTF-8 job.json → worker.py → result.json) nach dem vorhandenen K04-Worker-Muster. Der Worker verwendet nur Standardbibliothek, ffmpeg und optional den separat konfigurierten AMM-Interpreter. Der Adapter validiert Eingaben und Ergebnisse vor der Veröffentlichung, prüft die Stem-Hashes erneut, meldet Prozessfehler und räumt das temporäre Jobverzeichnis auf. Kein Import aus workers/ im Paket sirens/, kein In-process-Fallback.

Worker-Python wird explizit über worker_python=... oder SIRENS_PRODUCTION_MIX_PYTHON gewählt; andernfalls wird workers/production_mix/.venv/Scripts/python.exe (Windows) bzw. .venv/bin/python (POSIX) verwendet. In Tests wird sys.executable ausschließlich als Interpreter eines separaten Prozesses übergeben, damit für Standardbibliothek + ffmpeg keine zusätzliche venv installiert werden muss. Lokale Installation ohne Downloads: `py -3.11 -m venv workers/production_mix/.venv`.

Benötigt vorhandenes ffmpeg mit loudnorm, astats, acrossover, sidechaincompress; keine Downloads, kein Netzwerk im Offline-Mix. AMM-Interpreter nur in separater Worker-venv, freigegebener lokaler Checkout, kein Modellimport. Keine Live-Operation, keine zusätzlichen Daten im Git. Für einen neuen Run mit vollständigen, validierten plan.json und stems.json (zunächst realer 30–60-s-Groove, dann Vollsong):

```sh
py -3.11 -m unittest discover -s tests -v
python -c 'from pathlib import Path; from sirens.production.contracts import read_manifest; from sirens.production.mixing import mix; p=Path("PATH_TO_NEW_RUN"); print(mix(read_manifest(p/"plan.json"),read_manifest(p/"stems.json"),p))'
```

Optional im Python-Aufruf reference=Path("LOCAL_REFERENCE") für lautheitsangepassten A/B-Vergleich; amm_python=..., amm_root=... bei explizitem target_lufs für Mode C. SecondRoom lokal: fetch_chain("bass") usw. Nur Claude/Pal setzt geprüfte Gerätewerte. Revisionsparameter in plan.mix.tracks: gain_db, pan, highpass_hz, eq_hz, eq_db, reverb_send, delay_send; Wertebereiche im Adapter. Keine beliebigen Kommandos im Plan. Dry ist unprozessierte Summenvariante mit Randfade und Headroom, nicht ein Satz bearbeiteter Einzelspuren.

Erwarteter Output: WAVs und mix_report.json mit settings, dependencies, source_stems, dry/premaster/measured (lufs, true_peak_dbtp, lra, bands_dbfs, sub_side_mid_db, clipped_samples), warnings, listening=null; optional comparison. Echte Messwerte und Hörurteile erst nach Lauf ergänzen. Für reale Hörprobe Referenz und Master auf gleichem Pegel abspielen, technische Werte und konkrete subjektive Unterschiede getrennt protokollieren. Lizenzstatus von lokalem Audiomaterial vor Export prüfen; ffmpeg/AMM bleiben externe lokale Abhängigkeiten, keine Kopie ihrer Bibliotheken.
