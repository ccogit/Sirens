## Zielrechner: Aufruf und erwartetes Format

Bestehende WB-Daten/Plugins zuerst inventarisieren; Pfade sind operatorseitig konfigurierte lokale Pfade. Die Worker-venv muss vorhandene AMM-WB-Abhängigkeiten enthalten, kein Installationsbefehl im Skript. Keine Ausgabe in Git ablegen. PowerShell-Beispiel mit Platzhaltern:

```powershell
& $workerPython workers/production_instruments/inventory.py --amm-backend $ammBackend --inventory-dir $wbInventory --plugin $wbPluginRef
python workers/production_instruments/pilot.py --worker-python $workerPython --amm-backend $ammBackend --revision $actualVersions --patches $localPatchMaps --output $freshLocalOutput
```

Inventur gibt JSON mit inventory, presets, sample_instruments aus. Lokale Patchdatei ist ein Array aus drei Objekten; jedes enthält alle sieben semantischen IDs. Je ID Schema (Werte ausdrücklich Platzhalter, nicht installierte Presets):

```json
{"instrument":{"type":"vst3","plugin":"<WB-relative Pluginreferenz>","preset":"<tatsächliche WB-Preset-ID>","gain_db":-6},"revision":"<Preset-/Plugin-Fingerprint>","license":"unknown","use":"<bestätigte Nutzungsrechte>"}
```

Alternativ bestehender WB-State statt preset. Für alle drei Varianten unterschiedliche Bass-Preset-/State-Bindungen; Lizenz-/Nutzungsstatus vor Export überprüfen. Bei Mandoline/Cello zuerst vorhandene WB-Sampleinstrumente bzw. K04-Lieferungen prüfen; keine synthetische Attrappe. Ausgabe je Variante: plan.json, stems.json, stems/*.wav, sidechain-control.wav, stdout JSON mit Frames, Sample-Rate, Stem-Hashes, Peaks, Backend/Revision/Preset. Für Hörvergleich bestehende K05-Mixkette nutzen. Ziel: 48 kHz PCM24, 32,476 s, echte Kick-Onset-Abstände gegen 126 BPM, keine Clips, Renderzeiten/Versionen und Peak dokumentieren; anschließend G1 mit Nutzer. Kein automatischer Upload oder Download.

## Anpassungsbedarf

- K00/K08: Runner-Backend kann `render_stems(plan, assets, root, patches=..., backend=..., cache_dir=..., cancelled=...)` aufrufen. Cache-Verzeichnis ist übergeordneter lokaler Root, K00 HashCache erzeugt darunter cache/. Keine Änderung an K00. Die Sidechain-Datei ist zusätzliche Manifestmetadaten, nicht in stems[]; K05 muss sie explizit übernehmen.
- K02/K03: verbindliche semantische Patch-IDs aufeinander abstimmen. Nicht unterstützte Instrument-Parameterautomation (cutoff, resonance, modulation, sends etc.) muss vor realem Durchstich über bestehende WB-Parameterpfade umgesetzt oder als nicht unterstützt abgewiesen werden; kein stilles Ignorieren. Asset-Automation an K05 delegieren.
- K07: optionalen sicheren probe()/render()-Adapter erst nach positivem Spike anschließen. MIDI-/Automationsexport aus Plan, Audiofallback aus Stem, nie doppeltes Playback.
- Lokale Revisionen müssen tatsächlich aus Plugin/Preset/Host-Fingerprints bestimmt werden; derzeit verpflichtender, operatorseitiger Wert. Plugin-Seed-Steuerung nicht nachgewiesen; Seed ist Plan-/Cache-Provenienz, keine bitidentische native Synth-Zusage.
